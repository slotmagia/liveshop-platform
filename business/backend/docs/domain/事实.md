旧 Platform 授权表只允许作为一次性迁移输入；完成 Identity 持久导入回执校验并 finalize 后删除，不能再次成为运行时事实源。

店铺隔离是 `merchant_id + shop_id`。`app_id`/`commercial_id` 不是运行时标识，也不进入 Module Capability claims。Provider / SMS / Email / Storage 目录是无 `app_id` 的单全局目录。

## Live Provider 当前事实

- `DriverDefinition` 注册表拥有驱动 code、kind、推流形态、表单字段、默认值、枚举、凭据分组和校验边界；Admin 只解释该元数据。
- `live_provider` 是当前 Provider 目录；总后台维护单全局目录，业务键为 `code`，`code` 创建后不可变。
- `live_provider_version` 是 INSERT-only 的不可变版本快照，包含该版本运行所需非敏感配置与加密凭据。
- `live_provider_catalogue.revision` 是 Provider 目录写入修订号，也是并发命令的聚合锁；目录是 `id=1` 的单例。
- `live_provider_command` 是稳定 `commandKey` 的幂等回执；相同 key 不同请求摘要必须冲突。
- `platform_audit_event` 与 Provider 当前状态、版本快照和命令回执在同一事务提交。
- `health_status` 初始为 `UNKNOWN`；没有真实探测证据时页面显示“未检查”，不得伪造健康。

## 通知事件当前事实

- `NotificationDeclaration` 只存在于活动 Manifest 的 HTTP operation `notifications`。Admin 不能发明 `eventKey`。
- `platform_notify_event` 是活动声明投影，业务键为 `event_key`；`dispatchable` 跟随当前 Registry snapshot，投影按 `registry_revision` 可重放。
- `platform_notify_template_library` 是可复用模板，业务键为 `code`；`lifecycle` 为 ACTIVE/RETIRED。Admin 不能发明 `eventKey`。
- `platform_notify_event_policy` 拥有渠道开关、投递模式、`delay_seconds` 和每渠道 `templateCode`；首次投影写入默认策略：开启全部 `allowedChannels`，模式用 Manifest `defaultDispatch`。策略仍为 version=1 且该渠道模板为空时，若模板库已有约定 code `{eventKey}.{sms|email|in_app}` 则回填；否则保持为空直至 Admin 选择。本地 Compose seed 写入 Identity 登录 OTP 的 SMS/EMAIL 库模板。
- 短信/邮件 **通道、驱动、密钥** 仍由 sms / email capability 拥有；站内信 inbox 单例在 `platform_notify_inapp_config`。本事实不保存 Provider 账单或验证码对错。
- `platform_notify_delivery` 是一次渠道投递证据，幂等键 `(delivery_key, channel)`；请求摘要相同重放，不同则冲突。
- `platform_notify_attempt` 记录每次发送尝试；`platform_notify_inbox` 仅 IN_APP。

## 边缘路由与证书当前事实

详见 [`edge/事实.md`](./edge/事实.md)。Platform 不复制 Identity 自定义域名行；Ask/Route 实时查询 Identity。证书私钥只在 Caddy。

## 埋点事件当前事实

- `platform_telemetry_event` 是跨业务原始埋点事实。业务键为 `(merchant_id, shop_id, surface, event_id)`；重复写入只计 duplicate，不覆盖已落库行。
- 租户只来自 Identity Module Capability 的 `merchant_id + shop_id`。请求体不得携带 `app` / `appId` / `commercialId` / `uid`；若携带 `merchantId` / `shopId` 必须与 claims 完全一致。
- `surface` 与 `subject` 由服务端按当前 capability 写入：Shop 写入固定 `shop`，主体取 claims.Subject。客户端不能改写。
- Admin 只读浏览全部店铺事件，用于排查；不提供改、删或重放。广告触点旁路表、水位和归因投影尚未落库。
