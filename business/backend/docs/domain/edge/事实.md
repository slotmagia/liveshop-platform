# 边缘动态路由与证书事实源

Platform 拥有平台入口主机、CNAME 目标指令、证书准入策略，以及可选的 Caddyfile 生成与热加载。Identity 拥有自定义主机绑定和店铺 `code` / `subdomain`。证书私钥只存在于 Caddy，不入库。

## 旧系统到当前模型的逐项对照

| 旧表/接口 | 旧语义 | 当前事实 | 迁移规则 |
|---|---|---|---|
| `sys_config` 主域名字段 | 六个入口主机 + `force_https` | `platform_setting` namespace `domain-base` | 继续由 Admin 配置页版本化写入 |
| `custom_domain_cname_target` | 商户自定义域名 CNAME 目标 | `domain-base.custom_domain_cname_target` | 旧键迁入 Platform catalog；Identity 不再用 compose 静态串 |
| Caddy `on_demand_tls.ask` `/internal/domain-allowed` | classic HTTP，2xx 放行 ACME | `GET /internal/platform/edge/hosts/allowed` | 问 Platform；鉴权改为内部 grant（query `grant` 或头） |
| nginx `auth_request` `/internal/host-route` | 2xx + `X-Upstream` | `GET /internal/platform/edge/hosts/route` | 未绑定返回 403，避免网关把 404 当成 500 |
| `domain_binding` | 自定义主机与房间绑定 | Identity `identity_shop_domain` | Platform 实时查询 Identity，不复制行 |
| `{code}.{root}` | 平台子域名 | Identity `identity_shop.code` 然后 `subdomain` | 关闭店铺视为未绑定；本切片不含 `{roomCode}.{root}` |
| Caddyfile 热加载 | 保存主域名后 POST Caddy admin | `edge.enabled` 时 Apply | 本地 compose 默认关闭；配置先提交，Caddy 失败不回滚设置 |
| 证书行 / 私钥 | 旧项存在 | 不迁 | 私钥只在 Caddy |

## 唯一事实源

- 平台入口主机与 CNAME 目标：`platform_setting` `domain-base`。
- 自定义主机、TXT 挑战、主域名标记：Identity `identity_shop_domain`。
- 店铺短码与子域名：Identity `identity_shop`。
- 域名叠加层：Identity `identity_merchant_capability` `module=domains`。
- TLS 证书与私钥：Caddy 运行时存储，不是 Platform 表。

Platform 不消费 `identity.shop.domain.changed` 重建绑定副本。Ask / Route 每次实时问 Identity。
