# Platform 事务与失败窗口

## 激活

激活在一个 MySQL 事务中完成：

1. 锁定 Registry state 并读取当前 revision/活动发布。
2. 校验目标 release、Manifest 和权限定义。
3. 校验所有目标活动贡献的 `(surface, groupId)` 标题/排序一致性。
4. 更新活动 release。
5. 替换活动权限目录。
6. revision 加一并写 activation audit。
7. 提交。

步骤 1–6 任意失败均回滚；因此不会出现 Active 已变但目录/revision/audit 未变的部分状态。重复同一激活在写入前识别为幂等，不新增审计。

快照在同一只读视图中从 Registry state 构造，返回 revision 与对应活动发布。读取失败 fail closed，不返回混合版本。

## 授权数据交接

旧授权数据无法与 Identity 数据库形成跨库原子事务，因此采用显式两阶段运维：

1. Platform 在锁表快照中导出规范 JSON，计算 SHA-256，并持久化 export ledger。
2. Identity 验证并持久导入 IAM 子集；Subscription 验证同一 envelope 并持久导入 entitlement 子集。各自提交后签发绑定相同 export 的回执。
3. Platform `-finalize` 持久化并校验两份签收；Subscription 回执还绑定目标导入行数和投影摘要。只有两份都成立才删除旧授权表并标记 finalized。

任一目标导入失败或结果未知时不得 finalize；重新导入使用 digest 作为幂等边界。回执丢失时由对应目标从持久 ledger 重建，不能绕过验证人工删表。

## Live Provider 写入

每个 Put/Retire 命令在一个 MySQL REPEATABLE READ 事务中完成：

1. 创建并锁定 `live_provider_catalogue` 单例聚合行，串行化默认切换和不存在 key 的并发幂等请求。
2. 锁定并核对 `live_provider_command`；同摘要重放直接返回原不可变快照，不产生写副作用。
3. 按 ID 顺序锁定当前 Provider 目录，校验 `expectedVersion`、生命周期和默认项不变量。
4. 合并 KEEP/REPLACE/CLEAR 密钥命令；明文仅在进程内短暂存在，AES-GCM 加密后写入。
5. 更新/插入当前记录，并插入同版本不可变快照；切换默认时同步推进旧默认项版本。
6. 写命令回执、控制面 Audit，并将 catalogue revision 加一。
7. 提交。死锁/锁等待仅有界重试三次；校验错误、版本冲突和密钥错误不重试。

步骤 1–6 任一失败全部回滚。进程在提交前崩溃无可见副作用；提交后客户端未收到响应时，以原 commandKey 重试并返回原版本。并发携带同一 expectedVersion 的两个不同命令只有一个成功，另一个在聚合锁后看到新版本并冲突。

## 通知事件

模块激活与事件投影 **不是** 同一事务。Registry 激活提交后，Platform 按当前活动 snapshot upsert `platform_notify_event` 并补默认策略。投影失败不得回滚激活；Dispatch 在投影未跟上时 fail closed，worker 按 `registry_revision` 重放后恢复。

策略/模板库写入在一个 REPEATABLE READ 事务中：锁定命令回执、校验 expectedVersion、更新当前行、写 command 回执后提交。同摘要重放无副作用。Dispatch 按策略 `templateCode` 读取模板库，不再按 (eventKey, channel) 取旧表。

`Dispatch` 对每个启用渠道在一个事务中插入或重放 `(delivery_key, channel)`。发送（SMS/EMAIL Provider 或 Inbox 写入）发生在该行落库之后，不进入调用方业务事务。SYNC 等待该次发送达到 SENT / FAILED_PERMANENT / UNKNOWN；ASYNC/SCHEDULED 提交后即返回。

## 埋点写入

一次 Shop 上报在一个 MySQL REPEATABLE READ 事务中完成：逐行校验后对合法行 `INSERT IGNORE`，按 `(merchant_id, shop_id, surface, event_id)` 去重。非法行只进入响应 `errors`，不中止其余行。存储错误回滚整批；部分 rejected / duplicate 仍提交已成功插入。Admin 列表只读，无写事务。
