# Platform 不变量

1. 每个模块最多一个活动 release，活动 release 必须已经注册且 Manifest digest 已验证。
2. Registry revision 只在成功激活新活动状态后单调增加；重复激活同一版本不产生 revision、目录或审计副作用。
3. 所有活动 Manifest 中，同一 `(surface, groupId)` 的 `groupTitle` 与 `groupSort` 必须完全一致。不同 surface 可复用 groupId。
4. 导航冲突、权限冲突、Manifest 非法或数据库失败时，原 Active、Revision、活动权限目录与审计保持不变。
5. 路由快照和活动能力快照来自同一 Registry 事实源并携带同一 revision；快照读取无写副作用。
6. 活动能力快照只包含当前活动 release，并完整携带 backend、artifact、frontend、navigation、route、HTTP、gRPC 和 permission definition。
7. Gateway workload 只能读取路由快照；Identity workload 只能以 mTLS/SPIFFE 和独立 method permission 读取活动能力快照。浏览器不能直连。
8. Platform 只验证 Identity Module Capability，不签发它，不计算角色、策略、DataScope 或有效授权。
9. 通知 delivery key 和埋点 event ID 全局幂等；重复请求不得产生重复发送或重复事件。
10. Provider Secret 只保存密文或密钥引用，所有读取默认脱敏；外部调用超时进入 UNKNOWN 并通过查询、回调或对账恢复。
11. 广告归因和遥测投影可按 projector version 重建，不得反向推进业务模块状态。
12. Storage/Live Provider 分配与 Localization 发布必须校验 expected version；失败不改变活动配置或 Audit。
13. Platform 不保存验证码核验结果、游客风险决策、客服账号、商户治理状态、素材资产或直播房间/场次事实。
14. 旧授权数据 finalize 前必须验证 Identity receipt 绑定相同 schema/source/importId/digest/rowCount 且目标证据精确，不匹配不得删除任何表。
15. 单全局目录中的 Provider `code` 稳定且唯一；每次有效变更都将当前 `version` 加一，并在同一事务插入唯一不可变快照。店铺隔离只用 `merchant_id + shop_id`。
16. 平台全局分区最多一个 `ACTIVE + enabled + is_default` Provider；切换默认项时，被取消默认的 Provider 也必须推进版本并写快照。
17. Provider Secret、App Certificate、Customer Key/Secret 只保存 AES-GCM 密文；密文关联数据绑定 `code`（历史密文仍可用原 AAD 解密），浏览器和 Audit 永不返回或记录明文。
18. `RETIRED` 是 Provider 终态；退役只阻止未来分配/场次，不删除当前记录或历史版本。历史 Live 场次继续引用原 `code + version`。
19. Provider 写命令以 `commandKey` 幂等；相同摘要返回原版本快照，不新增版本、Audit 或 revision，不同摘要返回冲突。
20. Provider 的 `kind`、推流形态、可写配置字段和凭据组只由选定驱动定义；切换驱动必须清除新驱动不拥有的字段与凭据。
