# Platform → Identity / Subscription 旧授权数据交接

Platform 不再运行浏览器用户 IAM。历史角色/grant/scope 交给 Identity，历史商户 entitlement 交给 Subscription；没有运行时双读、双写或 fallback。

## 安全不变量

- Export payload 在数据库 advisory lock 下发现历史代际实际存在的表，再锁表并把规范 JSON 与 digest 原子写入 ledger；相同事实重复导出得到相同 SHA-256。
- 每个已知历史表都写入 `{name,present,rows}`；缺表和存在但空表不可混淆。至少一个历史表必须存在，发现后锁定/读取失败时不得当作空数据继续。
- Platform ledger 证明“导出了什么”，不能证明两个目标已导入，不能单独授权删除。
- Identity 与 Subscription 必须分别在自己的事务中以 payload digest 为幂等边界持久导入；提交后才能生成各自签名 receipt。
- Platform 必须验证两份 receipt 都绑定同一 source/schema/importId/digest/export rowCount，再校验各自 target/schema/key。Subscription receipt 额外绑定目标导入行数和投影摘要。两份证据均持久化后才允许删除旧表。
- 缺失、伪造、过期格式或任一字段不匹配时 fail closed，旧表保持不变。

## 阶段一：导出

```powershell
go run ./cmd/authorizationexport `
  -dsn '<platform-dsn>' `
  -output 'D:\secure-transfer\platform-authorization.json'
```

将输出文件通过受控渠道交给 Identity。重复运行会使用 Platform 的不可变 export ledger，并重写同 digest 的 envelope。

Envelope：

```json
{
  "schemaVersion": 1,
  "sha256": "<payload sha256>",
  "rowCount": 123,
  "payload": {
    "schemaVersion": 1,
    "tables": [
      {"name": "platform_authorization_role", "present": true, "rows": []},
      {"name": "platform_role", "present": false, "rows": []}
    ]
  }
}
```

## 阶段二：Identity 与 Subscription 分目标导入并签收

Identity 的导入器必须先验证 envelope digest/rowCount，在单个 Identity 数据库事务中写入授权事实和 import ledger。提交成功后，用专用 Ed25519 迁移回执密钥签名以下字段组成的紧凑 canonical JSON（字段顺序如下、无额外空白）的 UTF-8 字节：

```text
schemaVersion
source
importId
sha256
rowCount
imported
importedAt
targetIdentityInstance
targetIdentitySchemaVersion
keyId
```

Receipt 结构：

```json
{
  "schemaVersion": 1,
  "source": "liveshop-platform-authorization",
  "importId": "<Identity durable import ledger id>",
  "sha256": "<same payload sha256>",
  "rowCount": 123,
  "imported": true,
  "importedAt": "2026-08-14T08:00:00Z",
  "targetIdentityInstance": "identity-prod-cn",
  "targetIdentitySchemaVersion": 7,
  "keyId": "identity-authorization-import-1",
  "signature": "<base64url Ed25519 signature>"
}
```

专用私钥只存在于 Identity 导入环境；Platform 运维侧只接收对应公钥与 key ID。

Subscription importer 校验同一完整 envelope，只消费 `platform_entitlement_projection` 及商户 revision。它的 receipt 在上述共同字段外增加：`targetSubscriptionInstance`、`targetSubscriptionSchemaVersion`、`targetImportedRowCount`、`targetProjectionDigest`。全量 `rowCount` 表示验证过完整 export，并不冒充为目标实际写入行数。

## 阶段三：finalize

```powershell
go run ./cmd/authorizationexport `
  -dsn '<platform-dsn>' `
  -output 'D:\secure-transfer\platform-authorization.json' `
  -finalize `
  -identity-receipt 'D:\secure-transfer\identity-import-receipt.json' `
  -identity-receipt-key-id 'identity-authorization-import-1' `
  -identity-receipt-public-key '<base64url-ed25519-public-key>' `
  -identity-instance 'identity-prod-cn' `
  -identity-schema-version 7 `
  -subscription-receipt 'D:\secure-transfer\subscription-import-receipt.json' `
  -subscription-receipt-key-id 'subscription-authorization-import-1' `
  -subscription-receipt-public-key '<base64url-ed25519-public-key>' `
  -subscription-instance 'subscription-prod-cn' `
  -subscription-schema-version 3
```

命令先把两份完整 receipt 与各自 receipt SHA-256 写入独立 Platform ledger，然后删除退役表，最后写 `finalized_at`。任一证据缺失或不同均拒绝。MySQL DDL 中断后以完全相同的两份 receipt 重试收敛。

容器镜像同时包含 `/app/authorizationexport`，迁移作业必须显式覆盖默认 entrypoint，挂载只读 receipt/公钥输入和可写的受控导出目录。正常 Platform 服务不会调用该程序。

禁止人工删除旧表、伪造 receipt 或把 Platform 本地 export ledger 当成 Identity 导入证明。
