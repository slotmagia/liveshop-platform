# 数据库标准

- 每个业务事实只有一个数据库所有者；禁止跨模块直连数据表。
- migration 只追加，带稳定编号，生产由独立 migration job 在应用启动前执行。
- 同一数据库必须一致的写入放入同一事务；状态更新校验旧状态或版本。
- 数据库调用传递请求 context，并设置 statement/transaction deadline。
- 连接池必须显式配置 max open、max idle、max lifetime 和 max idle time。
- 热路径表采用规范化模型和必要索引；禁止用单行无限增长 JSON 文档承载整个业务域。
- 测试必须覆盖真实 MySQL 的约束、隔离级别、并发冲突、提交失败和重试收敛。

## 字符集与中文（强制）

全栈统一 **UTF-8 / MySQL `utf8mb4`**。中文显示成 `????` 通常表示**写入时已经丢字**，不是浏览器“显示问题”，必须沿链路排查并**重写正确数据**。

### 必须满足

| 环节 | 要求 |
|---|---|
| 服务端 | `character-set-server=utf8mb4`，`collation-server=utf8mb4_0900_ai_ci`（Compose `command` 已固定） |
| 库 / 表 | `DEFAULT CHARSET=utf8mb4`；标识符/token 列用 `utf8mb4_0900_as_cs`，展示名可用 `utf8mb4_0900_ai_ci` |
| 时间 | `DATETIME(3)` 存 UTC；服务 `default-time-zone=+00:00` |
| Go DSN | 必须含 `charset=utf8mb4&collation=utf8mb4_0900_ai_ci&parseTime=true&loc=UTC` |
| SQL 客户端 | `mysql --default-character-set=utf8mb4`（migrate / seed 脚本同此） |
| 源文件 | `module.json`、SQL、YAML、文档均为 **UTF-8（无 BOM）** |
| PowerShell | 读文本用 `[IO.File]::ReadAllText(path, [Text.Encoding]::UTF8)` 或 `Get-Content -Encoding utf8`；POST JSON 用 **UTF-8 字节** + `Content-Type: application/json; charset=utf-8`。禁止在 Windows PowerShell 5.1 上对含中文的文件使用默认 `Get-Content`（系统 ANSI 会把中文读成 `????`） |

### 排查顺序

1. **源文件字节**：编辑器/ `file` / HEX 确认 `module.json` 等已是 UTF-8 中文，不是 `????`。
2. **导入脚本**：注册、seed、migrate 是否按 UTF-8 读文件并以 UTF-8 发往服务端。
3. **连接会话**：`SHOW VARIABLES LIKE 'character_set%'`，client/connection/results 均为 `utf8mb4`。
4. **落库内容**：`SELECT HEX(col)` / 直接查 JSON 字段；若库内已是 `3F3F3F3F`（`????`），必须用正确字节**重新写入**，改显示层无效。
5. **HTTP 响应**：`Content-Type` 带 `charset=utf-8`；前端 HTML 有 `<meta charset="UTF-8" />`。

### 本地已踩过的坑

用 `register-platform-module.ps1` 注册 Platform 时，若未强制 UTF-8 读取 `module.json`，contribution `title`（「后台账户」「角色与组织」等）会以 `????` 写入 `platform_registry_state.releases`，侧栏导航即乱码。

处理：

1. 使用已修复的注册脚本（UTF-8 读文件 + UTF-8 body）；**新版本**可重新 `register` + `activate`。
2. 同版本不可覆盖（Registry 409）时，用 `go run ./tools/repair-registry-utf8.go -manifest ../module.json` 从 UTF-8 `module.json` 回填可读字段并递增 revision，Gateway 才会拉到新快照。
